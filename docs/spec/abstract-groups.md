# Abstract groups

Decided in wayfinder ticket
[Abstract group construction for every point-group family](https://github.com/hydeik/pointgroup-tables/issues/2).
Prototype: `prototypes/abstract_group_prototype.py` on branch
`prototype/abstract-group`.

## Model

A point group `G` is a subgroup of `R × {+1, −1}`, where `R` is a finite
**rotation group** handled as an abstract, exact integer object and the second
component is the **parity** (`+1` proper, `−1` improper). Every element of `G`
is the pair `(r, parity)`. The parity is part of the abstract group, not an
afterthought: `Ci` and `C2` are isomorphic as bare groups but have different
double groups, and only the parity tells them apart.

`G` is one of three **types**:

| Type | Name | Elements | Data |
| ---- | ------- | -------------------------------------- | -------------------------- |
| I | proper | `{(r, +1) : r ∈ R}` | `R` |
| II | centro | `R × {+1, −1}` | `R` |
| III | twisted | `{(r, χ(r)) : r ∈ R}` | `R`, index-2 subgroup `H`; `χ = +1` on `H`, `−1` elsewhere |

Products and inverses are componentwise: `(r, p)(r', p') = (r r', p p')`.

## Rotation groups

| `R` | Element | Product | Identity |
| --- | ------- | ------- | -------- |
| `Cn` | integer `k` mod `n` | `k + k'` mod `n` | `0` |
| `Dn` | `(k mod n, s ∈ {0, 1})`, meaning `C_n^k (C2')^s` | `(k + (−1)^s k', s + s')` | `(0, 0)` |
| `T` | permutation of 4 points (A4) | composition (`(pq)(x) = p(q(x))`) | identity permutation |
| `O` | permutation of 4 points (S4) | composition | identity permutation |
| `I` | permutation of 5 points (A5) | composition | identity permutation |

`T`, `O`, `I` are generated by breadth-first closure from fixed generators
(0-based, one-line notation):

| `R` | Generators |
| --- | ---------- |
| `T` | `(1 2 0 3)`, `(1 0 3 2)` |
| `O` | `(1 2 3 0)`, `(1 0 2 3)` |
| `I` | `(1 2 3 4 0)`, `(1 2 0 3 4)` |

No coordinate system is attached to any of these; which permutation is "the
C4 about z" is the business of a label convention.

## Canonical element order

Every table lists elements in this order, which depends on nothing but the
abstract group:

1. proper elements first (parity `+1`), then improper elements (parity `−1`);
2. within each parity block, elements follow the order of `R`:
   - `Cn`: `k = 0, 1, ..., n−1`;
   - `Dn`: `(0,0), (1,0), ..., (n−1,0)` then `(0,1), (1,1), ..., (n−1,1)`;
   - `T`, `O`, `I`: ascending rotation order (element order in `R`), then
     conjugacy class within `R` (ascending class size, ties broken by the
     smallest breadth-first index in the class), then breadth-first closure
     index. Conjugacy classes of `R` are therefore contiguous.

For type III groups the improper block contains exactly the `r ∉ H`, in `R`
order.

## Exposed structure

The output metadata of every table carries, for the group: `symbol`,
`input_symbol`, `family`, `n` (absent for polyhedral groups), `order`,
`type` (`proper` | `centro` | `twisted`), `rotation_group` (`C6`, `D4`, `O`,
...), and the parity of every element. Downstream chapters (double groups,
conjugacy classes, label conventions) build on `R`, the type and `H`.

## Verification

An implementation must pass, for every group it constructs:

- the group axioms on the Cayley table: closure, identity, inverses, and
  associativity, exhaustively for every group tested ([Verification](./verification.md#exhaustive-never-sampled));
- agreement of `(order, number of conjugacy classes, histogram of element
  orders)` with a checked-in table of known values; the seed is the 43 groups
  in the prototype (`C1` ... `Ih`, including `C5v`, `C7v`, `D7h`, `D8d`,
  `C8h`).

Stronger checks (characters against reference tables) belong to the
verification chapter.
